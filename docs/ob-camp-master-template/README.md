# SKIHEIL OB合宿管理｜マスターテンプレート（後継版）

「SKIHEIL OB合宿管理｜マスターテンプレート（複製元・直接使用しない）」スプレッドシートに
紐づく Google Apps Script のバックアップと仕様。

**合宿ごとにこのテンプレートを複製して使う方式。**
1 つのファイルを毎年使い回す旧方式は [`../ob-camp-template/`](../ob-camp-template/) を参照。

- コード取得日: 2026-09-22
- ソース: [`apps-script/`](apps-script/)

| ファイル | 内容 | 状態 |
| --- | --- | --- |
| [`apps-script/コード.gs`](apps-script/コード.gs) | Web アプリ本体、料金計算、日別集計、管理メニュー | 収録済み |

| | 年次テンプレート | マスターテンプレート（本書） |
| --- | --- | --- |
| 運用方式 | 1 ファイルを毎年使い回す | 合宿ごとに複製する |
| スキー場 | 片品 / 尾瀬岩鞍 | 片品 / 尾瀬岩鞍 / **丸沼** |

（丸沼の行がない）で実行すると `年度設定の値が不足しています: MARUNUMA_NORMAL` で止まります。

## 3. 年度設定のキー

`getConfig_` が読むキーの一覧。必須が 1 つでも欠けると Web アプリ全体が動きません。

| キー | 必須 | 内容 |
| --- | :-: | --- |
| `CAMP_NAME` | ● | 合宿名。Web アプリ上部に表示 |
| `EVENT_YEAR` | ● | 実施年度。アーカイブ名に使用 |
| `START_DATE` | ● | 開始日 |
| `END_DATE` | ● | 終了日。**この日は宿泊に選べない** |
| `STAY_NORMAL` | ● | 1 泊（夕食＋翌朝食込み） |
| `KATASHINA_NORMAL` | ● | 片品リフト 1 日 |
| `OZE_NORMAL` | ● | 尾瀬岩鞍リフト 1 日 |
| `MARUNUMA_NORMAL` | ● | 丸沼リフト 1 日 |
| `BUS_OUT` / `BUS_IN` | ● | バス（行）/（帰） |
| `CERTIFICATION` | ● | 検定 |
| `COMMON_FEE` | ● | 共通費。参加者 1 人につき 1 回 |
| `PASSWORD_MIN_LENGTH` | ● | 4〜32 の整数 |
| `EDIT_DEADLINE` | | 変更受付期限。空なら期限なし |
| `ADMIN_PASSWORD` | | 幹事の代理修正用。空なら管理者モードごと無効 |

日程は **1 日以上 45 日以内**（`getConfig_` の上限チェック）。

## 4. 料金計算

```
合計金額 = 宿泊費 + リフト費 + 交通費 + 検定費 + 共通費

宿泊費 = Σ 宿泊日ごとに  料金例外[日].宿泊費上書き ?? STAY_NORMAL

リフト費 = Σ リフト依頼日ごとに、リフト設定[日].指定スキー場 で単価が決まる
             片品     → 料金例外[日].片品上書き   ?? KATASHINA_NORMAL
             尾瀬岩鞍 → 料金例外[日].尾瀬岩鞍上書き ?? OZE_NORMAL
             丸沼     → 料金例外[日].丸沼上書き   ?? MARUNUMA_NORMAL
             未定 / 購入なし → 0

交通費 = (バス行 ? BUS_OUT : 0) + (バス帰 ? BUS_IN : 0)
検定費 = 受験する ? CERTIFICATION : 0
共通費 = 小計 > 0 のときだけ COMMON_FEE（何も選んでいない人には付かない）

状態 = 合計 > 0 ? '受付済' : 'キャンセル'
```

食事は宿泊日から自動で決まる（フォーム上で個別に外せる）。

```
夕食日 = 宿泊日そのもの
朝食日 = 宿泊日 + 1日（合宿期間内のみ）
```

## 5. 認証と権限

| 操作 | 必要なもの |
| --- | --- |
| 新規登録 | 氏名 + 編集用パスワード（本人が決める） |
| 登録内容の読み込み・変更 | 氏名 + 同じパスワード |
| 幹事の代理修正 | `?admin=1` 付き URL + `ADMIN_PASSWORD` |
| 仮パスワードの再発行 | スプレッドシートの**所有者**であること |

パスワードは `SHA-256(ソルト + "\n" + 氏名 + "\n" + パスワード)` を Base64 で保存し、
比較は `safeEqual_`（長さが同じ場合に定数時間比較）で行う。
ソルトは `Utilities.getUuid()` を 2 つ連結したもの。

`?admin=1` を付けない限り、管理者パネルは HTML ごと出力されない
（`doGet` のテンプレート変数 `adminEntry` で制御）。

### SKIHEIL 管理

| 項目 | 関数 | 動作 |

## 7. 自動再計算のしくみ

`onEdit`（簡易トリガー）が「年度設定」「料金例外」「リフト設定」の見出し行より下の編集を検知し、
`autoRecalculateCosts_` → `recalculateAllCosts_` で登録済み全員の金額を計算し直す。

料金を変えた瞬間に既存の登録も新しい金額になるため、旧版の
「本人が再保存するまで古い金額のまま」という問題は解消されている。

## 8. 復元手順

1. 新しい Google スプレッドシートを作り、`../ob-camp-template/README.md` §2 のシート構成を作る
   （本テンプレートでは「リフト設定」の選択肢に **丸沼**、「料金例外」に **丸沼料金上書き** 列、
   「年度設定」に **`MARUNUMA_NORMAL` / `EDIT_DEADLINE` / `ADMIN_PASSWORD`** が加わる）
2. 拡張機能 → Apps Script を開き、[`apps-script/`](apps-script/) の 3 ファイルを同名で貼る
   - `コード.gs` `TemplateOps.gs` … スクリプトファイル
   - `index.html` … HTML ファイル
3. ⚙ プロジェクトの設定 →「`appsscript.json` マニフェスト ファイルをエディタで表示する」に
   チェックを入れ、[`apps-script/appsscript.json`](apps-script/appsscript.json) の内容を貼る
4. 「年度設定」の必須キーをすべて埋める（§3）
5. デプロイ → 新しいデプロイ → ウェブアプリ／アクセス「全員」
6. メニュー「テンプレート運用 → Web アプリ URL を使い方シートへ反映」で URL を登録
7. 「SKIHEIL 管理 → 設定をチェック」で入力漏れを確認

## 9. コードを読んで気づいた点

バックアップとしてコードは**一切変更せずそのまま**収録している。以下は既知の挙動として記録するもの。

### 直す価値があるもの

1. **`readExceptions_` が「料金例外」の備考列を読めていない**
   `getRange(..., 5)` で 5 列（A〜E）しか読まないのに `row[5]`（F 列）を参照しているため、
   `note` は常に空文字になる。丸沼列が増えて日付/宿泊/片品/尾瀬/丸沼/備考 の 6 列構成に
   なったときの取りこぼしと思われる。計算には影響しない。

2. **`onEdit` が 1 セル編集ごとに全員分を再計算する**
   料金を数セル続けて直すと、そのたびに参加者全員のループが走る。
   簡易トリガーの実行時間上限（30 秒）があるため、人数が増えると
   「金額を再計算できませんでした」のトーストが出る可能性がある。

3. **パスワードハッシュが未設定の行は誰でも上書きできる**
   `verifyRegistrationPassword_` は `storedHash` か `salt` が空なら検証せずに return する。
   幹事が「参加者」シートに手で行を足すと、その人の登録は誰でも読み書きできる状態になる。
   手入力で行を追加しないこと。

### 把握しておけばよいもの

4. **`deriveMeals_` は定義されているが呼ばれていない**（朝食・夕食はフォーム側の値をそのまま使う）
5. **`splitDates_` だけ `Session.getScriptTimeZone()` を使う**（他は spreadsheet のタイムゾーン）
6. **氏名の先取りができる** — 新規登録は誰でも任意の氏名でできるため、
   先に登録された氏名はそのパスワードでしか編集できなくなる。部内利用なので実害は小さい。

### このコードを public リポジトリに置くことについて

コード内に URL・パスワード・スプレッドシート ID は一切含まれていないため、
公開しても認証情報が漏れることはない。ただし次の点は把握しておくこと。

- 認証の設計（`?admin=1` の入口、ハッシュの作り方）は公開される
- パスワードのハッシュは SHA-256 **1 回のみ**で、PBKDF2 のような反復処理がない。
  万一「参加者」シートが流出した場合、短いパスワードは総当たりで割られやすい。
  シート自体を公開しない運用を続けること（本リポジトリにも参加者データは収録していない）
