# SKIHEIL OB合宿管理（年次テンプレート）仕様書

Google スプレッドシート **「SKIHEIL OB合宿管理（年次テンプレート）」** と、そこに紐づく
Google Apps Script（コンテナバインド）で構成された OB 合宿の受付・集金管理ツールの仕様。

Drive 上のファイルが削除・破損した場合に、**この文書だけを見て同じものを組み直せる**ことを目的とする。

- スナップショット取得日: 2026-09-22
- 元ファイルの最終更新: 2026-08-20
- シート構成のスナップショット: [`snapshot/`](snapshot/)（CSV）

> **注意**: このリポジトリは public のため、スナップショットからは参加者の個人情報
> （氏名・金額・パスワードハッシュ・ソルト）と Web アプリの URL を除外している。
> 「参加者」「日別集計」シートはヘッダー行のみを収録。

## 1. 全体像

```
                OB（一般利用者）                幹事（管理者）
                      │                              │
              ブラウザで Web アプリ            スプレッドシートを直接開く
                      │                              │
                      ▼                              ▼
       ┌──────────────────────────┐   ┌─────────────────────────────┐
       │ Web アプリ（GAS / doGet） │   │ 使い方 / 管理ダッシュボード   │
       │ ・氏名＋パスワードで登録   │   │ 年度設定 / 料金例外 / リフト設定│
       │ ・宿泊日・リフト・バス・   │   │ 参加者 / 日別集計             │
       │   検定を選択               │   └─────────────────────────────┘
       │ ・金額は表示しない ★      │                  ▲
       └──────────────────────────┘                  │
                      │              保存時に金額を計算して書き込み
                      └──────────────────────────────┘
```

★ **設計上の要点**: Web アプリ側には金額を一切表示しない。
料金と入金状況は幹事がスプレッドシート上だけで扱う。

## 2. シート構成

7 枚のシートで構成される。

| # | シート名 | 役割 | 編集するのは |
| --- | --- | --- | --- |
| 1 | 使い方 | 運用手順と Web アプリ URL の掲示 | 幹事（初回のみ） |
| 2 | 管理ダッシュボード | 受付・入金状況の自動集計 | 自動（数式） |
| 3 | 年度設定 | 合宿名・日程・各種料金の設定 | 幹事 |
| 4 | 料金例外 | 特定日だけ料金が違う場合の上書き | 幹事 |
| 5 | リフト設定 | 日ごとに現役が行くスキー場を指定 | 幹事 |
| 6 | 参加者 | 登録データの本体 | Web アプリが自動書き込み |
| 7 | 日別集計 | 日ごとの宿泊者・食数・リフト枚数 | 自動（GAS が再生成） |

各シートとも **1 行目がタイトル、2 行目が説明文、3 行目が空行、4 行目がヘッダー、5 行目以降がデータ**
という共通レイアウト（「使い方」シートを除く）。A1:H1 と A2:H2 は結合セル。

### 2.1 年度設定

`A4:D4` がヘッダー、`A5:D16` が設定行。**C 列（値）が黄色セル**で、ここだけを編集する。
A 列のキーは GAS が参照するため変更しない。

| キー | 設定項目 | 例 | 説明 |
| --- | --- | --- | --- |
| `CAMP_NAME` | 合宿名 | 2027年 SKIHEIL 2合宿 | Web アプリ上部に表示 |
| `EVENT_YEAR` | 実施年度 | 2027 | アーカイブ名に使用 |
| `START_DATE` | 開始日 | 2026-02-10 | 合宿の初日 |
| `END_DATE` | 終了日 | 2026-02-19 | 合宿の最終日（この日は宿泊選択なし） |
| `STAY_NORMAL` | 宿泊費 | ¥7,700 | 1泊・夕食と翌朝食を含む |
| `KATASHINA_NORMAL` | 片品リフト | ¥3,000 | 1日あたり |
| `OZE_NORMAL` | 尾瀬岩鞍リフト | ¥6,300 | 1日あたり |
| `BUS_OUT` | バス（行） | ¥4,500 | 利用者のみ |
| `BUS_IN` | バス（帰） | ¥4,500 | 利用者のみ |
| `CERTIFICATION` | 検定 | ¥5,000 | 受験者のみ |
| `COMMON_FEE` | 共通費 | ¥8,000 | 参加者に1回だけ加算 |
| `PASSWORD_MIN_LENGTH` | パスワード最小文字数 | 4 | 4〜32 の整数 |

`START_DATE` / `END_DATE` は `=DATE(2026,2,10)` のような数式で入っている。

### 2.2 料金例外

通常料金と異なる日だけ行を追加する。空欄の項目は「年度設定」の通常料金を使う。

| 列 | 内容 |
| --- | --- |
| A | 日付 |
| B | 宿泊費上書き |
| C | 片品料金上書き |
| D | 尾瀬岩鞍料金上書き |
| E | 備考 |

例（2026年度）:

| 日付 | 片品料金上書き | 備考 |
| --- | --- | --- |
| 2026-02-11 | ¥5,000 | 片品特別料金 |
| 2026-02-13 | ¥5,000 | 片品特別料金 |
| 2026-02-14 | ¥5,000 | 片品特別料金 |

> 上書きは「その日の指定スキー場と一致したときだけ」効く。
> 上の例では 2/11・2/13・2/14 はリフト設定で「尾瀬岩鞍」になっているため、片品の上書きは適用されない。

### 2.3 リフト設定

`A4:C4` がヘッダー（日付 / 現役指定スキー場 / 備考）、`A5` 以降に合宿日程の各日が 1 行ずつ並ぶ。
日付セルは `=DATE(2026,2,10)` のような数式。

- **`B5:B49` にプルダウン（データの入力規則・リスト）**: `未定` / `片品` / `尾瀬岩鞍` / `購入なし`
- 日程が変わったらメニュー「SKIHEIL 管理」→「リフト日程を同期」で作り直す

### 2.4 参加者

登録データの本体。`A4:U4` がヘッダー、`A5:U504`（最大 500 名）がデータ領域。

| 列 | ヘッダー | 内容 |
| --- | --- | --- |
| A | 更新日時 | 最終保存時刻 |
| B | 登録ID | UUID |
| C | 氏名 | 本人入力 |
| D | 宿泊日 | `YYYY-MM-DD` のカンマ区切り |
| E | 朝食日（自動） | 宿泊日の **翌日** |
| F | 夕食日（自動） | 宿泊日の **当日** |
| G | リフト購入依頼日 | カンマ区切り |
| H | バス(行) | `利用する` / `利用しない` |
| I | バス(帰) | `利用する` / `利用しない` |
| J | 検定 | `受験する` / `受験しない` |
| K | 宿泊費 | 計算結果 |
| L | リフト費 | 計算結果 |
| M | 交通費 | 計算結果 |
| N | 検定費 | 計算結果 |
| O | 共通費 | 計算結果 |
| P | 合計金額 | K〜O の合計 |
| Q | 状態 | `受付済` など |
| R | 入金状況 | プルダウン |
| S | 備考 | 幹事が自由記入 |
| T | パスワードハッシュ | Base64。本人確認用 |
| U | ソルト | ハッシュ生成用 |

- **`R5:R504` にプルダウン**: `未確認` / `入金済` / `対象外`
- **幹事が手で編集してよいのは S 列（備考）と R 列（入金状況）だけ**
- K〜P 列（金額）は Web アプリには表示されない

### 2.5 日別集計

Web アプリ保存時と管理メニュー操作時に GAS が全面再生成する。
`A4:J4` がヘッダー、`A5` 以降に合宿日程の各日。

| 列 | ヘッダー |
| --- | --- |
| A | 日付 |
| B | 宿泊者数 |
| C | 宿泊者 |
| D | リフト購入依頼数 |
| E | 指定スキー場 |
| F | リフト購入依頼者 |
| G | 朝食数 |
| H | 朝食 |
| I | 夕食数 |
| J | 夕食 |

宿の食数手配とリフト券のまとめ買いに使う。

### 2.6 管理ダッシュボード

すべて数式。**復元時はこの 8 本をそのまま貼れば再現できる。**

| セル | 見出し | 数式 |
| --- | --- | --- |
| A5 | 受付済み人数 | `=COUNTIF('参加者'!$Q$5:$Q$504,"受付済")` |
| C5 | 請求予定総額 | `=SUMIF('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$P$5:$P$504)` |
| E5 | 未確認人数 | `=COUNTIFS('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$R$5:$R$504,"未確認")` |
| G5 | 未確認金額 | `=SUMIFS('参加者'!$P$5:$P$504,'参加者'!$Q$5:$Q$504,"受付済",'参加者'!$R$5:$R$504,"未確認")` |
| A9 | リフト依頼者 | `=COUNTIFS('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$G$5:$G$504,"<>")` |
| C9 | バス（行） | `=COUNTIFS('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$H$5:$H$504,"利用する")` |
| E9 | バス（帰） | `=COUNTIFS('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$I$5:$I$504,"利用する")` |
| G9 | 検定受験 | `=COUNTIFS('参加者'!$Q$5:$Q$504,"受付済",'参加者'!$J$5:$J$504,"受験する")` |

見出しセルは A4:B4 / C4:D4 / E4:F4 / G4:H4、値セルは A5:B6 / C5:D6 / E5:F6 / G5:H6 の結合。

## 3. 料金計算ロジック

```
合計金額 = 宿泊費 + リフト費 + 交通費 + 検定費 + 共通費

宿泊費 = Σ（宿泊日ごとに）
           料金例外[その日].宿泊費上書き があればそれ、なければ STAY_NORMAL

リフト費 = Σ（リフト購入依頼日ごとに）
           リフト設定[その日].指定スキー場 で単価が決まる
             片品     → 料金例外[その日].片品料金上書き ?? KATASHINA_NORMAL
             尾瀬岩鞍 → 料金例外[その日].尾瀬岩鞍料金上書き ?? OZE_NORMAL
             購入なし → 0

交通費 = (バス(行) == 利用する ? BUS_OUT : 0)
       + (バス(帰) == 利用する ? BUS_IN  : 0)

検定費 = (検定 == 受験する ? CERTIFICATION : 0)

共通費 = COMMON_FEE   // 参加者 1 人につき 1 回だけ
```

食事は宿泊日から自動で決まる。

```
夕食日 = 宿泊日そのもの
朝食日 = 宿泊日 + 1日
```

### 検算（2026年度の実データ）

日程 2026-02-10 〜 2026-02-19、リフト設定は
`2/10 片品, 2/11 尾瀬岩鞍, 2/12 片品, 2/13 尾瀬岩鞍, 2/14 尾瀬岩鞍, 2/15 片品, 2/16 片品, 2/17 片品, 2/18 片品, 2/19 尾瀬岩鞍`。

ある参加者（宿泊 8 泊 = 2/13 を除く 2/10〜2/18、リフト 10 日全部、バス・検定なし）の場合:

| 項目 | 計算 | 金額 |
| --- | --- | --- |
| 宿泊費 | 8泊 × ¥7,700 | ¥61,600 |
| リフト費（片品） | 2/10,2/12,2/15,2/16,2/17,2/18 = 6日 × ¥3,000 | ¥18,000 |
| リフト費（尾瀬岩鞍） | 2/11,2/13,2/14,2/19 = 4日 × ¥6,300 | ¥25,200 |
| 交通費 | 利用しない | ¥0 |
| 検定費 | 受験しない | ¥0 |
| 共通費 | 1回 | ¥8,000 |
| **合計** | | **¥112,800** |

スプレッドシート上の実値と一致することを確認済み。
（料金例外の 2/11・2/13・2/14 片品 ¥5,000 は、これらの日の指定スキー場が尾瀬岩鞍のため不適用。）

## 4. 運用手順

### 4.1 最初に行うこと

1. 「年度設定」の黄色セルで合宿名・年度・日程・料金・パスワード条件を確認する
2. 「リフト設定」で現役が行くスキー場を日ごとに 1 つ指定する
3. 特定日だけ料金が違う場合は「料金例外」に上書き料金を入力する
4. Web アプリ URL を OB へ案内する。本人は氏名と編集用パスワードで登録・変更する

### 4.2 毎年の更新手順

1. 年度設定の「実施年度」「開始日」「終了日」と各料金を新年度の内容に変更する
2. メニュー「SKIHEIL 管理」→「リフト日程を同期」を実行し、日ごとのスキー場を指定する
3. 「料金例外」を新日程に合わせて修正し、「設定をチェック」で入力漏れを確認する
4. メニュー「新年度を開始」を実行する。旧データは保存され、同じ Web アプリ URL を継続利用できる

### 4.3 カスタムメニュー

| メニュー | 項目 | 動作 |
| --- | --- | --- |
| SKIHEIL 管理 | リフト日程を同期 | 年度設定の開始日〜終了日から「リフト設定」の行を作り直す |
| SKIHEIL 管理 | 設定をチェック | 年度設定・リフト設定・料金例外の入力漏れを検出する |
| SKIHEIL 管理 | 新年度を開始 | 参加者データをアーカイブし、新年度の受付を開始する |

### 4.4 既知の制約

> **料金変更後、すでに登録済みの人の金額は自動再計算されない。**
> 本人が Web アプリで読み込み、再保存すると新料金になる。

この制約は後継版の「マスターテンプレート」で解消されている（§6 参照）。

## 5. Apps Script（要・別途バックアップ）

このスプレッドシートには **コンテナバインドの Google Apps Script** が紐づいており、
Web アプリ本体・料金計算・日別集計の再生成・カスタムメニューはすべてそこに実装されている。

**コンテナバインドスクリプトのソースコードは Drive API からは取得できない。**
スプレッドシートを削除するとスクリプトも一緒に消えるため、**コードは別途エクスポートして
[`apps-script/`](apps-script/) に置く必要がある。**手順は [`apps-script/README.md`](apps-script/README.md) を参照。

想定されるファイル構成:

| ファイル | 内容 |
| --- | --- |
| `コード.gs` / `Code.gs` | `doGet` / `doPost`、料金計算、日別集計の再生成、`onOpen` でのメニュー登録 |
| `index.html` | Web アプリの登録フォーム |
| `appsscript.json` | マニフェスト（タイムゾーン、`webapp.access: ANYONE` など） |

デプロイ設定: 種類「ウェブアプリ」／アクセスできるユーザー「全員」。

## 7. 復元手順

1. 新しい Google スプレッドシートを作成する
2. [`snapshot/`](snapshot/) の各 CSV を、同名のシートとしてインポートする
   （CSV には数式ではなく計算結果が入っているため、§2.6 の数式と §2.1・2.3 の
   `=DATE(...)` は手で入れ直す）
3. データの入力規則を設定する
   - リフト設定 `B5:B49` → リスト `未定, 片品, 尾瀬岩鞍, 購入なし`
   - 参加者 `R5:R504` → リスト `未確認, 入金済, 対象外`
4. `apps-script/` のコードを「拡張機能 → Apps Script」に貼り戻す
5. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」／アクセス「全員」でデプロイする
6. 発行された URL を「使い方」シートに記入し、OB へ案内する
7. 「SKIHEIL 管理」→「設定をチェック」で入力漏れがないか確認する

> 参加者データは本リポジトリに含まれていない。過去の登録内容ごと復元したい場合は、
> スプレッドシートの `.xlsx` エクスポートを別途（public でない場所に）保管すること。
